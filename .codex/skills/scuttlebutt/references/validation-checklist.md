# Scuttlebutt Validation Checklist

Run through these passes after completing the analysis to ensure quality and completeness.

---

## Pass A: Stakeholder Completeness

All 6 stakeholder categories must be covered. Check each:

- [ ] **Customer Voice** — Section present with quantitative metrics and qualitative themes
- [ ] **Employee Voice** — Section present with Glassdoor/Indeed data and culture assessment
- [ ] **Partner/Supplier Voice** — Section present (or explicit "limited data" acknowledgment)
- [ ] **Competitor Voice** — Section present with positioning analysis
- [ ] **Industry Expert Voice** — Section present with analyst/rating agency sentiment
- [ ] **Social/Media Sentiment** — Section present with news tone and short interest

**If a category has limited data:**
- Explicitly state what was searched and not found
- Assign a confidence level (High/Medium/Low)
- Do NOT fabricate findings to fill the template

---

## Pass B: Evidence Quality

### Quantitative Metrics

For each stakeholder with available data:

- [ ] **Source identified** — Platform name (Glassdoor, J.D. Power, Trustpilot, etc.)
- [ ] **Rating captured** — Numeric score (X.X/5, X%, ranking)
- [ ] **Sample size noted** — Number of reviews/data points
- [ ] **Trend indicated** — Direction (↑/→/↓) or YoY comparison

### Representative Quotes

- [ ] **At least 3-5 verbatim quotes** across stakeholder categories
- [ ] **Source attribution** — Where each quote came from
- [ ] **Balance** — Both positive and negative sentiment represented
- [ ] **Recency** — Quotes from last 1-2 years preferred

### Customer Voice Sources (check applicable)

| Industry Type | Primary Sources |
|--------------|-----------------|
| B2B Software | G2, Capterra, TrustRadius, Gartner Peer Insights |
| Consumer Products | Amazon, Trustpilot, BBB, Consumer Affairs |
| Insurance | J.D. Power, NAIC complaints, CRASH Network |
| Financial Services | J.D. Power, CFPB complaints, NerdWallet |
| Financial Infrastructure (Exchanges, Clearing) | Trade publications (Risk.net, FIA), regulatory complaints (CFTC), industry forums |
| Enterprise Tech | Gartner, Forrester, TrustRadius |
| Retail/Hospitality | Yelp, Google Reviews, TripAdvisor |
| Healthcare | Healthgrades, Vitals, CMS ratings |

At least 3 sources should be consulted for Customer Voice.

**B2B Infrastructure Exception:** For pure B2B infrastructure companies (exchanges, clearing houses, enterprise infrastructure), consumer review platforms (G2, Capterra, TrustPilot) are often not applicable. In these cases:
- [ ] Note "N/A - B2B model" for inapplicable consumer platforms
- [ ] Substitute industry-specific sources (trade publications, regulatory filings, institutional feedback)
- [ ] Weight professional/institutional sources more heavily

## Pass C: Scoring Accuracy

### Scuttlebutt Health Score

- [ ] **All 6 stakeholders scored** — Each has a 1-5 score
- [ ] **Weights sum to 100%:**
  - Customers: 30%
  - Employees: 25%
  - Partners: 15%
  - Competitors: 10%
  - Industry Experts: 10%
  - Media/Social: 10%
- [ ] **Weighted calculation correct** — (Score × Weight) summed
- [ ] **Overall score matches sum** — Math verified
- [ ] **Score consistency across documents** — The SAME score must appear in ALL THREE locations:
  1. Analysis Executive Summary ("Scuttlebutt Health Score: X.X / 5.0")
  2. Analysis Scorecard table ("Overall" row)
  3. Memo header ("Scuttlebutt Health Score: X.X / 5.0")
  - If these differ, recalculate and update all locations before proceeding

### Score Calibration

| Score | Definition | Check |
|-------|------------|-------|
| 5 | Exceptional — Consistently positive, no concerns | Rare; requires overwhelming evidence |
| 4 | Strong — Mostly positive with minor concerns | Common for quality companies |
| 3 | Mixed — Balanced positive and negative | Appropriate when genuinely split |
| 2 | Concerning — More negative than positive | Requires specific evidence |
| 1 | Poor — Pervasive negative sentiment | Rare; requires overwhelming evidence |

- [ ] **Scores justified by evidence** — Each stakeholder score defensible from findings
- [ ] **No score inflation/deflation** — Honest assessment, not optimistic/pessimistic

## Pass D: Red Flags & Moat Implications

### Red Flags

- [ ] **Red flags table present** — Even if "none identified"
- [ ] **Each red flag has:**
  - Severity rating (High/Medium/Low)
  - Stakeholder source
  - Specific evidence
  - Moat implication
- [ ] **Severity calibration:**
  - HIGH: Could materially impact investment thesis
  - MEDIUM: Worth monitoring, not thesis-critical
  - LOW: Minor concern, low probability or impact
- [ ] **Overall red flag status** — Clean / Minor Concerns / Moderate Concerns / Significant Concerns

### Moat Implications

- [ ] **Customer signals → moat assessment** — What customer sentiment reveals about competitive position
- [ ] **Employee signals → operational health** — What employee sentiment reveals about talent/culture moat
- [ ] **Partner signals → ecosystem strength** — What partner sentiment reveals about ecosystem moat
- [ ] **Competitive signals → positioning** — What competitor behavior reveals about defensibility
- [ ] **Overall moat validation status:**
  - Validated — Grassroots confirms moat thesis
  - Partially Validated — Core moat confirmed, some challenges
  - Challenged — Evidence contradicts moat thesis
  - Inconclusive — Insufficient data to assess

## Pass E: Investment Relevance

### Actionable Conclusions

- [ ] **"Trust" list** — What aspects of company narrative are validated
- [ ] **"Discount" list** — What aspects should be viewed skeptically
- [ ] **"Monitor" list** — What metrics/signals to track going forward

### Monitoring Dashboard

- [ ] **At least 5 metrics** with:
  - Current value
  - Warning threshold (specific number, not "declining" or "unknown" — if exact threshold unavailable, provide estimated threshold with "(est.)" note)
  - Monitoring frequency (Quarterly/Monthly/Annual)
- [ ] **No vague thresholds** — Every metric must have an actionable numeric threshold
- [ ] **Early warning signals** — Specific observable indicators by stakeholder

### Cross-Stakeholder Analysis

- [ ] **Pattern analysis present** — Themes mentioned by multiple stakeholders
- [ ] **Sentiment divergence noted** — Where stakeholder groups disagree
- [ ] **Positive patterns** — Consistent strengths across groups
- [ ] **Concerning patterns** — Consistent weaknesses across groups

## Pass F: Output Structure

### Analysis Document

- [ ] **Executive Summary** — 3-4 paragraphs, overall assessment, health score
- [ ] **Scorecard table** — All 6 stakeholders with weights and key signals
- [ ] **6 stakeholder sections** — Each with Overview, metrics, themes, summary
- [ ] **Pattern Analysis section** — Cross-stakeholder themes
- [ ] **Red Flags section** — Table with severity ratings
- [ ] **Moat Implications section** — 4 stakeholder-type tables + overall assessment
- [ ] **Monitoring Dashboard section** — Metrics and early warning signals
- [ ] **Data Sources section** — Sources consulted, limitations, search queries
- [ ] **Conclusion section** — Overall assessment and investment implications

### Customer Voice Subsections

- [ ] **Switching Intent Signals** — Mentions of switching to competitors, reasons for leaving, lock-in vs. loyalty assessment
- [ ] **Customer Support Quality** — Support ratings, common complaints, praise (or "data not available" note)

### Employee Voice Subsections

- [ ] **Culture Dimension Scores** — Glassdoor dimension breakdown (work-life balance, compensation, etc.) if available, or note if not found
- [ ] **CEO Approval sourced** — Company-wide CEO approval from Glassdoor OR Comparably CEO score. If Glassdoor doesn't display company-wide CEO approval publicly (increasingly common), Comparably CEO score (X/100) is acceptable as the primary metric. Note in limitations if Glassdoor data is unavailable. Never present role-filtered data (e.g., "9% for Senior Directors") as if it were company-wide.
- [ ] **Blind data captured** — Blind rating and dimension scores if company has Blind presence, OR explicit "Blind: Not available" note
- [ ] **Comparably data captured** — Culture score and CEO score from Comparably if available, OR explicit "Comparably: Not available" note

### Memo Document

- [ ] **Header** — Health score (MUST match Analysis scorecard), assessment, date
- [ ] **Key Takeaways** — 5-7 bullets with bold lead-ins; MUST include switching intent signal if customer data shows it
- [ ] **Scorecard table** — Simplified (Score + Key Signal); Overall score MUST match Analysis
- [ ] **What Stakeholders Love** — Table with at least 4 rows + Moat Signal summary below
- [ ] **What Stakeholders Complain About** — Table with at least 4 rows + Severity column + Moat Risk summary below
- [ ] **Red Flags to Monitor** — Checklist format with warning thresholds
- [ ] **Moat Implications table** — Aspect + Signal + Validation column (must contain: Validated, Challenged, or Neutral for each row)
- [ ] **Bottom Line** — 2-4 sentence synthesis
- [ ] **Quick Reference** — Key metrics table (must include: Health Score, Glassdoor Rating, CEO Approval if available, Customer Review Avg, Short Interest, Red Flag Status). Note: Customer Review Avg is an average of review platform ratings (Trustpilot, App Store, etc.), NOT the ACSI score — these are different metrics. If review platforms diverge significantly, show both (e.g., "4.8 app / 1.7 web").

### File Naming

- [ ] **Analysis:** `[Company]/2.2-Scuttlebutt/Scuttlebutt - Analysis - [Company] - [YYYY-MM-DD-HHMM].md`
- [ ] **Memo:** `[Company]/2.2-Scuttlebutt/Scuttlebutt - Memo - [Company] - [YYYY-MM-DD-HHMM].md`

## Pass G: Data Integrity

### Source Verification

- [ ] **No fabricated data** — All metrics traceable to actual sources
- [ ] **Recency noted** — Data freshness indicated (2024, 2025, etc.)
- [ ] **Sample sizes reasonable** — Don't overweight single reviews

### Limitations Disclosure

- [ ] **Data gaps acknowledged** — What couldn't be found
- [ ] **Search queries listed** — For reproducibility
- [ ] **Confidence levels stated** — Where data is thin

### Intellectual Honesty

- [ ] **Balanced assessment** — Not just hunting for problems
- [ ] **Skeptical of extremes** — Very positive/negative reviews may be planted
- [ ] **Divergence explained** — When sources conflict, explain why
- [ ] **No overclaiming** — Score reflects evidence, not optimism
- [ ] **Estimates clearly labeled** — Inferred data marked with "(est.)" or "(inferred)" throughout, not just in one place
- [ ] **Metric types distinguished** — Different metrics (customer service vs. satisfaction vs. NPS) not conflated

---

## Quick Reference: Common Failures

| Failure | How to Fix |
|---------|------------|
| Missing stakeholder category | Search again or explicitly note "no data found" |
| No quotes/evidence | Add representative quotes with sources |
| Inflated/deflated scores | Recalibrate against scoring definitions |
| Red flags without severity | Add High/Medium/Low rating with justification |
| Generic moat conclusions | Connect specific findings to specific moat aspects |
| Missing monitoring metrics | Add 5+ metrics with warning thresholds |
| Memo doesn't match Analysis | Ensure Memo synthesizes (not contradicts) Analysis |
